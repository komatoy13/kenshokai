# 顕正会 報告システム — ファイル構成

元の `index.html`（1ファイル・3,184行）を、**中身を1行も変更せずに**分割したものです。

## 使い方

`index.html` をダブルクリックするだけで動きます（file:// で動作。サーバー・ビルド不要）。
フォルダ構造を崩さずに、3つをまとめて同じ場所に置いてください。

```
kenshokai-system/
├── index.html       画面のHTML（562行）
├── css/
│   └── style.css    スタイル（153行・メニューとグラフ用を含む）
└── js/              25ファイル
```

## 方式

- ES Modules は **使っていません**。従来の `<script src="...">` を依存順に並べています。
- したがって `onclick="gasLoad()"` などのHTML属性からの呼び出し、グローバル変数（`hanList`, `HAN` など）はすべて従来どおり動きます。
- 読み込み順を変えると壊れます。番号順（01→21）を維持してください。

## 更新履歴（分析機能の追加）

「分析」タブ（設定タブの右隣、支隊長のみ表示）を追加しました。集計データを表にまとめて、Claudeなどへのコピペ・アップロード用に出力できます。

### 変更点

1. **`saveResult()`（結果保存）の挙動を変更**（js/07-aggregate.js）
   - 従来：同じ日付で複数回結果保存すると、後の保存が前の保存を丸ごと上書きしていた（データ消失のバグ）→ 同日は項目単位・氏名単位で追記マージするよう修正
   - 追加：結果保存のたびに、支隊全体の合計だけでなく**氏名ごとの掴み・結果のスナップショット**も `aggHistory[].members` に保存されるようになった（これが個人別の推移分析のもと）
2. **既存の不具合を修正**（js/13-data-reset.js）
   - 「すべてのデータを初期化」の後、`aggHistory` が配列ではなくオブジェクトになり、集計履歴の表示がエラーになる不具合を修正
3. **新規ファイル `js/22-analysis.js` ＋ index.html に「分析」タブ（pg7/tb7）を追加**
   - 項目（全項目デフォルト選択）／班／期間を指定
   - 「表を作成」：支隊全体の推移をMarkdown表で画面プレビュー →「表をコピー」でクリップボードにコピー（Claudeへの貼り付け用）
   - 「個人別CSVダウンロード（集計項目）」：氏名ごとの掴み・結果の推移をCSVで出力
   - 「入信者リストCSVダウンロード（折伏成果）」：名簿の入信日をもとに、期間内の入信者一覧をCSVで出力
   - 班長・副長モードには表示されません（支隊長専用）

### 日曜勤行の「掴み」について

現在、日曜勤行では事前の掴み（ABC評価）を運用していないとのことですが、機能自体は残しています。分析の表では「日曜勤行(掴み)」列は空欄になるだけで、支障はありません。掴みを引き続き使っている項目（総部集会など）ではそのまま見立てと実績の差を確認できます。

### 動作確認

- 既存33ファイル全体の構文チェック（`node --check`）を実施
- jsdom（Node.js上のDOM環境）で実際に index.html を読み込み、以下を確認済み：
  - 同日に複数回結果保存しても、先の記録が消えず、両方の項目が履歴に残ること
  - 氏名ごとの掴み・結果が `aggHistory[].members` に正しく記録されること
  - 「分析」タブの表プレビューが正しい数値（結果人数・掴みの加重合計）で生成されること
  - CSV出力ロジック（ダウンロード直前の `URL.createObjectURL` 呼び出しの手前まで）が既存のバックアップ機能と同じ方式で、エラーなく動作すること

### ≡メニュー（右下フローティング）

### グラフ（メニュー →「グラフ」）
外部ライブラリは使わず、SVGを自前で描画します（オフラインでも動作）。上部の「項目」「期間」「班」で切り替えます。
1. 項目別の推移（折れ線）
2. 掴み（ABC加重）と結果の比べ（棒。掴みを使っている項目で表示）
3. 折伏成果の推移（棒）
4. 個人別 ○× 一覧（行＝氏名、列＝日付。傾向「増／減／横ばい」付き。記録4回以上）

- 操作：タップ（PCはホバー）でその日の数値、各グラフの「数値表」で全数値を確認できます。グラフ上の数字は最新と最大のみ。
- 表示範囲：
  | 役職 | 表示 |
  |---|---|
  | 支隊長 | 支隊全体。班を選ぶと「その班」＋「支隊全体（合計）」を並べて表示 |
  | 副長 | 「担当班まとめ」または担当の各班 ＋ 支隊全体（合計） |
  | 班長 | 自班 ＋ 支隊全体（合計） |
  班長・副長には、支隊全体は合計だけを出し、担当外の班の数値・個人名は出しません（名簿の閲覧制限と同じ、画面上の制限です）。
- データの出どころ：支隊全体＝`aggHistory[].summary`、班別・個人別＝`aggHistory[].members`、折伏成果＝`hHist`。
  **班別・個人別は、個人別記録の保存を追加した版で「結果保存」した分から蓄積されます。** それ以前の記録は支隊全体の合計のみです。

## 更新履歴（報告日・上書き確認・ABC一括クリア）

### 報告日を自動で「今日」にする（js/01-constants.js, js/21-boot.js, js/06-tabs.js）
- 以前は起動時に1回だけ日付を入れており、しかもUTC基準（日本の午前0〜9時は前日）でした。アプリを開きっぱなしにすると、前回の日付が残る原因になっていました。
- 今は端末の日本時間で「今日」を計算（`todayLocal()`）し、次のタイミングで報告日を今日に合わせます：起動時／アプリに戻ったとき／集計・折伏成果タブを開いたとき／保存に成功したあと。
- 同じ日のうちに手で日付を変えた場合は、その選択を尊重します。日をまたぐと今日に戻ります。
- 同じ原因だった「メールの段取り（今日〜翌週月曜）」「折伏予定の過去判定」の日付計算も直しました（日本時間の午前0〜9時にメールを作ると、翌週月曜の予定が漏れていた）。

### 上書き確認（js/07-aggregate.js `saveResult`、js/08-shakubuku.js `saveHR`）
- 同じ報告日・同じ項目の記録がすでにあるときだけ、保存前に確認が出ます。「2026年10月18日(日) … 日曜勤行：3人 → 5人」のように、日付（曜日つき）と今の記録・今回の内容を並べて表示します。報告日が今日でない場合は注意書きも付きます。
- 「キャンセル」すると何も変わりません（日付はそのまま残るので、直して保存し直せます）。
- 同じ日付でも別の項目なら確認は出ず、従来どおり追記されます。
- 上書きした項目は、個人別記録も入れ替わります。

### ABCを一括クリア（js/07-aggregate.js `clearAllGrab`）
- 集計タブの「リセット」の隣に「ABCを一括クリア」ボタンを追加。
- 対象は「いま選択している項目」×「表示中の班（全班まとめなら全員）」。確認ダイアログに対象項目・範囲・件数が出ます。
- ABC（掴み）だけを消します。結果（○×・数値）は消えません。

### 日曜勤行の既定（js/07-aggregate.js `getItemMode`）
- 日曜勤行は最初から「結果」入力の状態です（○×ボタン）。手で「掴み」に切り替えることもできます。リセット後も結果入力に戻ります。他の項目の既定は従来どおり（掴み）です。

### 動作確認（jsdom・日本時間・時刻固定）
午前0時台の日付、日またぎ、上書き確認の各分岐（新規／同じ項目／別の項目／キャンセル）、一括クリアの範囲、日曜勤行の既定、メール段取り：62項目合格。前回のグラフ・メニューの59項目も引き続き合格。
